# C1: plan loader, rules R1 and R2, text output

Date: 2026-11-12

## What this milestone delivers

- `src/plan_review/model.py`: pydantic model of the parts of the plan JSON the rules
  read. Unknown keys are ignored; a `format_version` other than 1.x and an action list
  Terraform does not emit are rejected with a one-line reason.
- `src/plan_review/actions.py`: classification of `change.actions` into no-op, create,
  read, update, delete, forget, and replacement in either order, including the
  `forget, create` and `create, forget` forms Terraform writes when a resource with
  `lifecycle { destroy = false }` is replaced.
- `src/plan_review/stateful.py`: the explicit list of AWS resource types that hold data.
- `src/plan_review/rules.py`: R1 (stateful resource destroyed) and R2 (stateful
  resource replaced, in either order; when the old object is only forgotten the finding
  says so), both high severity and therefore blocking.
- `src/plan_review/report.py` and `src/plan_review/cli.py`: the `plan-review` command,
  plain-text report, exit status 0, 1 or 2.

The command on each sample plan:

| Plan | Findings | Exit status |
|------|----------|-------------|
| `no_changes` | none | 0 |
| `create_baseline` | none | 0 |
| `iam_widened` | none (R3 is not written yet) | 0 |
| `exposure` | none (R4 and R5 are not written yet); its stateless delete is ignored | 0 |
| `destroy_stateful` | R1 on the database, the EFS file system and the bucket; the IAM policy delete is ignored | 1 |
| `replace_stateful` | R2 on the database and the volume (delete, then create) and on the bucket (create, then delete); the ingress rule replacement is ignored | 1 |

A missing file, invalid JSON, an unsupported `format_version` or an unknown action list
exits with status 2 and a message on standard error.

## Facts established while building this milestone

- Terraform leaves attributes that are known only after apply out of `after` entirely
  (for example `arn` on a replaced database); `after_unknown` marks them with `true`.
- `replace_paths` names the attributes that force a replacement, and `action_reason`
  says why (for the sample plans, `replace_because_cannot_update` and
  `delete_because_no_resource_config`).
- A replacement has four spellings in `change.actions`: `["delete", "create"]`,
  `["create", "delete"]` (`create_before_destroy`), and, when the resource block has
  `lifecycle { destroy = false }`, `["forget", "create"]` or `["create", "forget"]`. In
  the last two the old object leaves Terraform state and keeps running; the managed
  object at that address is still new and empty, so R2 reports them too. The JSON format
  page does not list the two `forget` forms; Terraform's plan serializer writes them.
- Sensitive values appear in clear text in `before` and `after`; only
  `before_sensitive` and `after_sensitive` mark them. The tests insert a sensitive
  value into the sample plans and check it never reaches a finding or the report.
