# C0: project scaffold and sample plans

Date: 2026-11-12

## What this milestone delivers

- `pyproject.toml` managed with uv: Python 3.12 or newer, ruff, mypy in strict mode,
  pytest.
- CI on every pull request: format check, lint, type check and tests on Python 3.12 and
  3.13, plus a job that regenerates the sample plans and fails when a committed plan
  differs from its source.
- Six sample plans under `fixtures/plans/`, generated from the scenarios under
  `fixtures/terraform/` without any AWS account, plus `scripts/generate_fixtures.py`.
- `tests/test_fixtures.py`: every plan loads, has the Terraform plan JSON shape, and
  contains the change shapes its scenario documents.
- ADR-0001: the tool reviews the plan delta, not the state.

## Commands run and results

Environment: Linux x86_64, uv 0.13.7, Terraform 1.17.2, AWS provider 6.73.0. The four
checks were run twice, once with CPython 3.12.3 and once with CPython 3.13.15, with the
same results.

```sh
uv sync --locked
uv run ruff format --check .   # passed: every file already formatted
uv run ruff check .            # All checks passed!
uv run mypy                    # Success: no issues found in 3 source files
uv run pytest                  # 21 passed
```

Fixture generation and reproducibility, with Terraform 1.17.2 on `PATH`:

```sh
uv run scripts/generate_fixtures.py          # six plans written
uv run scripts/generate_fixtures.py --check  # six plans up to date, exit 0
```

The second command regenerates every plan in a temporary directory and compares it byte
for byte with the committed file, so a plan that is up to date after a fresh run is a
plan that Terraform reproduces deterministically once the timestamp is removed. The
provider is downloaded once into a temporary plugin cache for the whole run, both
locally and in CI.

## Facts established while building the fixtures

- With `-refresh=false`, placeholder credentials, the `skip_*` provider settings and
  every endpoint pointed at a closed local port, Terraform plans creations, in-place
  updates, destructions and both replacement orderings entirely offline for
  `aws_s3_bucket`, `aws_s3_bucket_public_access_block`, `aws_iam_policy`,
  `aws_vpc_security_group_ingress_rule`, `aws_db_instance`, `aws_ebs_volume` and
  `aws_efs_file_system`.
- `aws_dynamodb_table` calls `DescribeTable` while planning a change to an existing
  table, so it cannot appear in a scenario with prior state. It was replaced by other
  stateful types.
- Provider 6.x records a `region` attribute on every regional resource. A seed state
  without it makes Terraform plan an in-place update that only sets `region`; the seeds
  therefore include it. Resources built on the plugin framework (the ingress rule)
  distinguish `tags = {}` from no tags, so the seeds leave `tags` out for them.
- A plan with no changes still lists every resource in `resource_changes` with the
  action `no-op`.
- The only field that varies between two runs of the same scenario is the top-level
  `timestamp`, which the generator removes.
